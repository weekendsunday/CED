# 语义差分驱动的漏洞挖掘平台 — 技术方案

> **文档定位**：内部实施文档（工程向）
> **类别**：**漏洞挖掘（挖掘类，非防护类）**
> **服务场景（唯一，已锁定）**：我们作为服务提供商 → 客户把产品交给我们 → 我们检测**产品之间的耦合误差**
> **约束**：作品赛 · **15 天** · **4 人** · 无 GPU · **代码从零开始**

---

## 0. 类别定位：挖掘 vs 防护（先划清界限）

| | 防护类（本方案**不做**） | **挖掘类（本方案）** |
|---|---|---|
| 起点 | **已知**漏洞（CVE / 补丁） | **未知**，只有规格与多个实现 |
| 终点 | 受影响资产清单、修复排期 | **新发现的可触发漏洞** + PoC |
| 代表产物 | SCA / 影响面判定 / SBOM 治理 | 差分挖掘 / fuzzing / 漏洞研究 |
| 成功标准 | 漏报率、响应时间 | **发现了多少前人没发现的漏洞** |

**非目标**：不做资产治理、不做 SCA 增强、不做补丁回移监控、不做修复排期。这些是防护类的活儿，与本作品无关。

## 0.1 目标对象：差异出在组件之间，不在组件里

**目标对象不是"某个程序"，而是"同一规格的多个实现及其组成的链路"。**

> 单独看 nginx 没问题，单独看 gunicorn 没问题，`nginx + gunicorn` 就有 desync。
> **漏洞不在组件里，在组件之间的语义缝隙里。**

| 层 | 内容 | 本期范围 |
|---|---|---|
| 规格层 | HTTP/1.1 消息分帧（RFC 9112）、URL/路径归一化（RFC 3986 + 实现私有行为）、编码 / Unicode 归一化、序列化格式 | HTTP/1.1 分帧为主线；第二领域在 P3 落地 |
| 实现层 | **前置**：nginx / haproxy / Envoy / Apache httpd / Varnish<br>**后端**：Gunicorn、h11、hyper、Node `http`、Go `net/http`、Tomcat、Jetty、Werkzeug | 全部开源、可容器化、可离线快照 |
| **组合层** | 前置 × 后端 的 **N×M 链路对** | **≥ 8×8** —— 只有组合层才是漏洞的载体 |

**被探测的分歧轴（HTTP/1.1 分帧，可穷举）** —— 这是"15 天能做完"的原因：不泛泛 fuzz HTTP，而只打在有限且已知有分歧历史的语法点上。

- **Content-Length**：前导零、`+` 号、空白、超大值、重复头、非数字字符
- **Transfer-Encoding**：重复出现、非标准 token（`xchunked`）、大小写、多 TE 组合
- **CL 与 TE 同时存在时**的优先级（CL.TE / TE.CL / TE.TE 的根源）
- **chunk 语法**：chunk 扩展、大小进制、CRLF 变体（裸 LF）、结尾终止条件
- **头解析**：obs-fold 折行、头名前后空格、行终止符不统一
- **请求行**：绝对 URI vs 相对 URI、方法大小写

## 0.2 服务形态与输入输出契约（唯一场景）

| 项 | 内容 |
|---|---|
| **我们是谁** | 服务提供商（检测方） |
| **客户是谁** | 产品方（网关 / 中间件 / 云平台 / 集成商…） |
| **客户给什么** | ① 产品本身（**镜像**，黑盒，**不要求源码**）② 产品之间的**串联方式**（拓扑 + 关键配置） |
| **我们给什么** | **耦合误差报告**：误差清单 + 安全影响分级 + 最小复现样本 + 修复建议 |
| **不做什么** | 不扫域名、不做资产治理、不要求客户交出源码、不做未授权测试 |

### 核心概念：耦合误差

> **耦合误差 = 两个产品在串联处，对同一份数据的理解不一致。**

产品单独工作都正常，**串起来才出现**——所以客户自己测不出来（他们各自测各自的）。这正是这项服务的价值来源。

### 交付流程

```
1. 客户提交：产品镜像 + 拓扑（谁在前、谁在后、怎么转发）
2. 我们起容器，按客户拓扑真实串联
3. 灌入探测请求 → 收集每个产品的"理解"
4. 比对 → 找出耦合误差
5. 判定哪些有安全影响 → 生成最小复现样本
6. 交付报告：全量误差 + 安全分级 + 修复建议
```

**输入示例**

```yaml
domain: http1-framing
topology:                     # 客户真实的串联方式
  - product: customer-gateway:3.2     # 客户自研，客户提供镜像
    role: front
  - product: tomcat:10                # 开源，我们从公共仓库拉
    role: back
```

**关键约束**：客户给的是**镜像**而不是源码 → 全程黑盒使用。这既是客户能接受的信任边界，也正好匹配差分技术（不需要读代码）。

## 1. 核心洞察：挖掘的瓶颈是 **oracle**，不是变异

| 方式 | 判据 | 能发现什么 |
|---|---|---|
| 单实现 fuzzing | 崩溃 / sanitizer 报错 | **只有会崩的缺陷**；解析差异、鉴权绕过、过滤器绕过全漏 |
| **差分** | **两个实现对同一输入语义不一致** | 解析差异、归一化差异、边界解释差异 |
| **差分 + 可升级性判定** | 分歧 ∧ 攻击者可控 ∧ 有安全后果 | **请求走私 / 鉴权绕过 / WAF 绕过 / 缓存投毒** |

差分是唯一**不需要崩溃、不需要 LLM、不需要 GPU、不需要人工标注**的通用 oracle。

$$\text{漏洞} \iff \text{语义分歧} \;\wedge\; \text{分歧点攻击者可控} \;\wedge\; \text{存在安全后果}$$

**攻击者可控性**是抑制"兼容性噪音"的唯一有效过滤器——两个实现不一致但攻击者无法选择落到哪一侧的，是兼容性问题，不是漏洞。

## 2. 创新点

### 核心 ① 语义分歧的自动「可升级性判定」
- **现状**：差分测试产出大量"实现不同"的结果，人工逐个判断是否是漏洞，无法规模化，这也是差分技术长期停留在论文里的原因。
- **做法**：内置**分歧类型 → 安全后果**映射表（下表），结合"攻击者能否控制分歧点"做自动分类，把原始分歧分为 `security / compatibility / unknown`。
- **度量**：可升级比例、`security` 类的精确率。

| 分歧类型 | 安全后果 | 现状 |
|---|---|---|
| 请求边界 / 长度解释（HTTP/1.1 分帧） | 请求走私（CL.TE / TE.CL / TE.TE）→ 前置防护绕过 | **已实现** `http1-framing`（9 实现 / 8 轴） |
| 路径归一化 | 鉴权绕过、路径穿越（含过长 UTF-8、NUL 截断） | **已实现** `url-norm`（12 实现 / 11 轴） |
| Host / 路由归一化 | 虚拟主机绕过、缓存投毒 | **已实现** `host-norm`（9 实现 / 8 轴） |
| 参数 / 查询串解析 | 参数污染 → 认证绕过、逻辑绕过 | **已实现** `query-norm`（11 实现 / 10 轴） |
| 编码 / Unicode 归一化 | 过滤器绕过 → XSS / SQLi | **已实现** `enc-norm`（10 实现 / 10 轴） |
| 错误处理 / 状态机 | 状态绕过、信息泄露 | 规划中（加领域即可接入） |

> **这张表必须按「现状」列读**：前五行是代码里真的能跑出来的（各有已知案例反验证），
> 只有最后一行是规划。
> 加一个领域的成本 = 语料 + 分类 + 消融实验设计 + 量化口径 + PoC 片段；
> 引擎、判定器、最小化、报告、控制台、落库**一行都不用改** ——
> 这已由第 2~5 个领域反复验证（`@register` 一行即接入）。

### 核心 ② 判别输入（distinguishing input）的自动构造与最小化
- **现状**：找到"两实现不一致"容易，找到**能稳定区分两者**的最小输入很难，人工调试耗时。
- **做法**：从种子变异出的候选 → 用差分 oracle 筛选 → **语义保持的 ddmin 最小化** → 输出最小判别样本。
- **新意**：判别样本本身就是可提交的 PoC 骨架。
- **度量**：最小化后的样本长度、判别稳定性（重复运行一致率）。

### 支撑 ③ N×M 组合矩阵的规模化编排
- **做法**：容器化每个实现，并行跑全组合矩阵，幂等复跑，输出热力图。
- **度量**：矩阵覆盖率、单组合平均耗时。

### 支撑 ④ 从分歧到攻击场景的自动升级
- **做法**：`security` 类分歧套用场景模板（走私 / 绕过 / 投毒）生成端到端 PoC。
- **度量**：可升级为可复现攻击的案例数。

### 核心 ⑤ 大模型的边界契约（判定字段在类型上无法表达）
- **现状**：LLM 扫描器的通病是"说得像真的"。业界做法是提示词约束 + 人工复核，不可规模化；
  更糟的是让模型直接给结论，产出无法复核的判定。
- **做法**：模型在引擎里只有**一个**位置 —— **结论之后的解读者**。它只在确定性内核
  出完级之后被调用，把已经定好的证据翻译成人话（真实后果 / CWE 建议 / 修复建议），
  挂成报告里一栏明确标注「非判定」的附注。搜索方向由领域适配器的轴与定向变异确定，
  模型不参与。
- **为什么是真创新**：幻觉不是被"抑制"，而是**在类型上写不出来** ——
  `Interpretation` 里没有任何判定字段，模型多塞的 `level` / `cwe` / `verdict`
  在解析时被直接丢弃；调用失败一律降级回内核原文案。
  "用大模型"与"被大模型带偏"之间是**代码级不变式**，不是提示词纪律。
- **度量**：幻觉字段丢弃率（模型塞判定字段时是否一个都进不了结构）、
  降级覆盖率（未配模型 / 不可达 / 输出不合形时，报告是否照出且判定一字不变）。

## 3. 技术点（模块 → 成熟底座 → 自研增量）

| # | 模块 | 成熟技术（直接用） | 自研增量（评审看点） |
|---|---|---|---|
| 1 | 领域适配器 | HTTP 解析链、URL/路径归一化、编码/Unicode、序列化 | **规格建模 + 输入空间描述**（如何变异才落在分歧点上） |
| 2 | 变异引擎 | 自研定向轴变异（分歧语法点穷举 + 模板变异，零第三方依赖） | 面向**分歧探测**而非崩溃的变异策略与反馈 |
| 3 | 差分 oracle | 多实现执行 + 结果归一化 | **结果等价性定义**（哪些差异算"语义分歧"而非表现差异） |
| 4 | 可升级性判定 | 规则引擎 | **分歧→安全后果映射表 + 消融定位承载者**（核心资产） |
| 5 | 最小化 | ddmin | 语义保持约束（最小化后仍必须保持分歧） |
| 6 | 编排 | Docker / docker-compose、任务队列 | 矩阵调度、幂等复跑、结果去重 |
| 7 | 报告 | JSON / Markdown | 分歧证据 + 判别样本 + 攻击升级路径 |
| 8 | 模型解读层 | OpenAI 兼容 HTTP（urllib） | **判定之后的解读者**：只认 `impact` / `cwe_hint` / `fix` 三个键，判定字段在类型上不存在；失败即降级回内核原文案，报告只加不判 |
| 9 | 扫描控制台 | Python 标准库 `ThreadingHTTPServer` | 后台任务 + 手写 `text/event-stream` 事件流；**模型文字与确定性证据分栏**渲染 |

**技术栈**：Python（编排与判定，标准库零依赖）+ Docker（实现隔离）+ 自研定向变异轴 + 各语言原生实现（差分对象）。**不需要 GPU。**

大模型是可插拔的**旁路**：它只在结论出来之后解读（怎么读），搜索方向与判定权完全在内核。
不配置模型时全链路自动降级为纯确定性模式，扫描照跑、报告照样出 ——
详见 §12「大模型辅助层：边界契约」。

## 4. 系统架构

```mermaid
flowchart TD
  S[规格 + 实现清单] --> P[输入空间建模 / 种子池]
  P --> M[变异引擎<br/>语法感知 + 覆盖反馈]

  U -- compatibility --> Z[归档为兼容性问题]

  U -- security --> D[最小化 → 判别样本]
  D --> E[攻击场景模板升级]
  E --> R[报告 + PoC + 热力图]
```

## 5. 接口契约与数据模型

### 5.1 领域适配器接口

```python
class DomainAdapter(Protocol):
    def implementations(self) -> list[ImplSpec]: ...      # 参与差分的实现
    def seed_pool(self) -> list[bytes]: ...               # 初始语料
    def mutate(self, seed: bytes) -> Iterator[bytes]: ... # 语法/状态感知变异
    def normalize(self, impl: ImplSpec, out) -> Canon: ...# 结果归一化（关键：定义"等价"）
    def classify(self, divergence) -> Kind: ...           # 分歧 → 类型映射
```

### 5.2 数据模型（SQLite）

| 表 | 关键字段 |
|---|---|
| `impl` | impl_id, name, version, image_ref, role(前置/后端/库) |
| `case` | case_id, adapter, payload, minimized_len, stable_rate |
| `divergence` | case_id, impl_a, impl_b, kind, canonical_diff |
| `verdict` | divergence_id, level(security/compat/unknown), reason, cwe |
| `poc` | divergence_id, scenario(desync/bypass/poison), script_path, verified |

## 6. 指标体系

| 类别 | 指标 | 目标 |
|---|---|---|
| 挖掘产出 | **确认的可升级漏洞数** | ≥ 3（含 ≥1 端到端可复现攻击） |
| 有效性验证 | **已知漏洞再发现率** | 对已知 desync/绕过案例，平台能重新挖出 ≥ 1 个 |
| 效率 | 原始分歧 → 唯一分歧的压缩比 | 优化后显著下降（去重 + 最小化） |
| 精度 | `security` 类判定的精确率 | ≥ 60% |
| 规模 | 客户拓扑链路覆盖 / 交叉矩阵覆盖 | 客户链路 100%；交叉矩阵 ≥ 8×8 |
| 速度 | 单组合单 case 平均耗时 | 秒级 |

**可靠性验收方式（关键）**：用**已知漏洞反验证**——平台能否重新发现公开的请求走私 / 路径绕过案例。这解决"挖不到就等于没用"的举证难题：**先证明能复现已知，再证明能发现未知。**

## 10. 服务定位：产品耦合误差检测（唯一场景）

**一句话**：客户把产品交给我们，我们找出它们**串联时的耦合误差**。

### 客户为什么自己测不出来

| 客户能测的 | 客户测不了的 |
|---|---|
| 单个产品的功能、性能、自身的已知漏洞 | **两个产品串起来之后的语义不一致** |
| A 单独跑正常，B 单独跑也正常 | A + B 一起跑才出现的缝 |

### 客户画像

| 客户 | 典型的"产品串联" |
|---|---|
| 网关 / 中间件厂商 | 自研网关 → 自研服务框架（或用了 nginx） |
| 云厂商 / 平台方 | 负载均衡 → API 网关 → 微服务运行时 |
| 集成商 / 政企 | 多个厂商的产品拼成一套系统 |
| 车机 / 嵌入式 | 多个组件串在同一条数据链上 |

### 测试范围（两类组合）

| 组合 | 目的 |
|---|---|
| **客户真实拓扑链路** | 直接对应客户生产环境，必测 |
| **客户产品 × 参考实现矩阵** | 放大发现能力——同一产品也可能与其它实现耦合不一致，暴露客户尚未遇到的场景 |

第二类很关键：只测客户自己那条链，样本太少容易漏；把客户产品与一批标准实现交叉组合，一次能给客户更多价值。

### 交付物

**耦合误差报告**：全量误差清单 + 安全影响分级（`security` / `compatibility` / `unknown`）+ 最小复现样本 + 修复建议。

### 内部基准（不交付，仅用于证明平台有效）

公开组件矩阵（nginx / haproxy / Envoy / Tomcat / gunicorn …），用**已知的请求走私案例反验证**：平台能否重新挖出公开案例。这是平台有效性的证据，不是交付内容。

## 11. 演示脚本（2 分钟）

**场景**：客户提交两个产品——自研网关 + 一个开源运行时——声称线上串着用。

1. 加载客户产品镜像与拓扑（网关在前、运行时在后）。

## 12. 大模型辅助层：边界契约（可测试的不变式）

> 一句话：**判定与搜索全在内核；模型只在结论出来之后解读。**

这是"用大模型"与"被大模型带偏"的分界线。它不是提示词纪律，而是**代码级不变式**。

### 12.1 模型只有一个位置：判定之后

| 环节 | 谁来做 |
|---|---|
| 往哪里搜（语料 / 轴 / 优先级） | 确定性内核：领域适配器自带的轴 + 定向变异 |
| 是不是漏洞、什么级别 | `ced/classify/upgradability.py::judge()`（**唯一生产者**） |
| 这段结论怎么读 | `ced/assist/interpret.py::interpret()`（模型，可选、默认关） |

模型**看不到判定过程**，也**没有任何字段能写结论** —— 它拿到的是内核已经算好的
判定结果与证据文本，任务只有一个：把它们翻译成人话。

### 12.2 类型隔离

```python
@dataclass(frozen=True)
class Interpretation:    # ced/assist/interpret.py
    impact: str          # 真实后果
    cwe_hint: str        # CWE 建议
    fix: str             # 修复建议
    model: str
    ok: bool
    error: str
    # 没有 level / cwe / verdict / scenario —— 判定字段在类型上就不存在
```

- `Verdict` 的唯一生产者是 `judge()`；解读层**不在它的调用链上任何位置**。
- 解析只认 `INTERPRET_KEYS = ("impact", "cwe_hint", "fix")`：模型自作主张塞进来的
  `"level": "security"`、`"cwe": "CWE-444"` 一律**丢弃**，不进任何结构。
- 提示词**不喂原始字节**：只给判定结果与证据文本，免得模型越过解读去自己重做一遍差分。
- 每段文字有长度上限（`impact` / `fix` 各 400 字、`cwe_hint` 160 字），防止刷爆报告。

### 12.3 降级路径（现场演示的保险）

| 情况 | 行为 |
|---|---|
| 未配置 `CED_LLM_*` | `ok=False`，只保留内核原文案 —— **判定与结果一字不变** |
| 模型不可达 / 超时 / 输出不是 JSON | 同上，`error` 写明原因，检测继续 |
| 删掉整个 `ced/assist/` 目录 | 引擎、报告、控制台照跑（该层是旁路，不是依赖） |

解读是**纯加法**：报告里原有那几行确定性文案一行不动，模型说的话另起一栏、明确标注
「非判定」；页面上勾了就升为主内容，没勾就完全不出现。

### 12.4 合规边界

只把内核已经算出来的**判定结果与证据文本**发给模型。
**不发客户镜像、不发原始流量、不发原始字节、不发客户拓扑文件。**

### 12.5 命令与接口

| 命令 / 接口 | 用途 |
|---|---|
| `python -m ced web` | 检测页 / 设置里勾「使用模型解读」（设置项 `detect.interpret`，默认关） |
| `GET /api/assist/status` | 模型配置状态（侧栏左下角那行状态就是它） |
| `POST /api/detect`（带 `interpret: true`）· `GET /api/detect/events`（SSE） | 检测：判定跑完再补一栏模型解读 |
| `POST /api/scan/start` · `GET /api/scan/events`（SSE）· `GET /api/scan/result` · `POST /api/scan/abort` | 扫描任务与事件流 |


### 13.1 攻击场景升级：端到端 PoC（补齐 §2 创新点④）

模块：`ced/scenario/`（`templates.py` 场景数据 + `poc.py` 生成）。

- **只对 `security` 级发现升级**。`unknown` / `compatibility` 一律不出 —— 判定器没升级的，
  这里不许替它升级。有测试守着（`TestNoOverstatement`）。
- 每个 PoC 三件套：**叙事**（场景 / 影响 / 前提 / 步骤）、**字节归属**
  （前置转发 / 后端消费 / 夹带，数字来自 `orchestrate.chain` 的链式模型）、
  **可执行脚本**（零依赖，离线算账；`--send HOST:PORT --i-am-authorized` 才真发）。
- 落库表 `poc`（见 §5.2 数据模型），落盘默认 `results/pocs/poc_<case_id>.py`。
- 命令：`python -m ced poc <case_id>`；`scan` 自动产出全部 PoC。

### 13.2 指标与交叉矩阵热力图（补齐 §2 支撑③、§6 指标体系）

模块：`ced/metrics.py`。

- `scan_metrics(result, elapsed)`：安全占比、**消融定位率**、唯一化压缩比、
  最小化压缩比、单用例平均耗时 —— 口径写死在实现里，报告与前端共用。
- `matrix_heatmap(result, impl_ids)`：N×N 矩阵，**对称**（同一条发现在 `[左][右]` 与
  `[右][左]` 都记），对角线为空；格子按最严重级别与命中数染色。
- 控制台：`/api/scan/metrics`、`/api/scan/heatmap` + 指标卡与热力图面板。

### 13.3 链路语义修正：前置拒绝 ≠ 链路故障

`ced/probe/errors.py` 新增 `ProbeRejected`，与 `ProbeUnreachable` 分开：

| 情况 | 判据 | 处置 |
|---|---|---|
| 链路故障 | 前置不可达 / 探针控制口不通 | `ProbeUnreachable` → **中止**，不产出任何结论 |
| 前置拒绝 | 前置回了响应，但探针没有视角 | `ProbeRejected` → **跳过该用例并计数**（`ScanResult.rejected_cases`） |

为什么必须分开：真实 nginx / Envoy 对畸形请求返回 4xx 且不向后端转发，属正常行为。
若当作链路故障，一轮扫描会在第一条畸形请求上崩掉，对真实产品完全不可用。
跳过**不合成观测**，也不静默 —— 计数会出现在 CLI 输出、报告与 `result_payload` 里。

### 13.4 第二领域：URL / 路径归一化（攻击面从 1 类扩到 2 类）

模块：`ced/impls/path_norm.py`（归一化内核）+ `ced/impls/url_reference.py`（10 个参照实现）+
`ced/mutate/url_axes.py`（语料/变异/消融变换）+ `ced/adapters/url_norm.py`（适配器）。

判定的是：**同一段请求目标被前置与后端解成了不同资源** ——
前置按自己的归一化结果做鉴权（放行），后端按自己的归一化结果路由（命中受保护资源）。
9 条轴全部有真实先例：`..` 解算、解码层数、百分号大小写、反斜杠、连续斜杠、
尾随点、矩阵参数、路径大小写、`%2F`。

**这次扩张最值得讲的事**：引擎、判定器、报告、控制台、PoC **一行都没改**，
但过程中逼出了三处**原先焊死在分帧上的领域耦合**，都被收进了适配器协议：

| 原先硬编码 | 现在归谁 | 后果 |
|---|---|---|
| `LocalEvaluator` 固定用分帧解析器 | `ImplSpec.domain` + `impls.LOCAL_PARSERS` 注册表 | 才能跑第二个领域的本地实现 |
| **消融实验**固定按"逐条移除请求头" | `DomainAdapter.ablate` | 否则路径分歧永远定位不到承载者 → 全判 `unknown`（实测：124 分歧 / **0** 安全级） |
| **最小化**固定按"请求头行"切 | `DomainAdapter.minimize` | 否则 URL 样本永远压不小（实测：13→13 字节） |
| **链路量化**固定调分帧注册表 | `DomainAdapter.quantify` | 否则第二个领域一跑就 `KeyError: 'url-gateway'` |

所以"加领域不改引擎"这句话**现在是成立的** —— 但它是在做第二个领域时才真正成立的，
不是一开始就成立的。这四处改动本身就是最好的证据。

> `security` 的口径两个领域一致：**结构性前提成立 ∧ 差异字节可控**，
> 不等于已被利用。每条发现都配最小复现样本 + 可执行 PoC 供人复核。

### 13.5 另外三个领域：Host / 查询串 / 编码（攻击面 2 类 → 6 类）

在 `url-norm` 之后又加了三个领域，全部**只新增文件**、引擎零改动：

| 领域 | 观测对象 | 轴 | 漏洞类别 | CWE |
|---|---|---|---|---|
| `host-norm` | Host 头的值 | 8（尾随点、大小写、默认端口、userinfo、重复点、IDN、IPv6 字面量、百分号） | 虚拟主机绕过 / **缓存投毒** | CWE-436 |
| `query-norm` | 查询串字节 | 10（分隔符含 `;`、重复参数取首/取尾/全要、解码层数、`+`、空值、`a[]`、大小写、排序） | **参数污染** | CWE-235 |
| `enc-norm` | 一段待解释的字节 | 10（过长 UTF-8、NFC/NFD、全角、`%uXXXX`、代理项、字节编码、NUL） | **过滤器绕过** | CWE-180 |

`url-norm` 也补了两条轴：**过长 UTF-8**（`%c0%ae` 被接受即等价于 `.`）与 **NUL 截断** ——
为此把解码从"逐字节 Latin-1"改成"转义 → 字节 → 按策略 UTF-8 解码"，
才能把"过长编码"这件事表达出来。

### 13.6 验证层：做扫描器的裁判（输入面变宽）

`ced/intake/`：把**别人的发现**变成待验证的假设。

| 输入 | 提取 |
|---|---|
| nuclei（JSON / JSONL） | `matched-at` / `host` |
| Burp sitemap XML | `<item><url>` |
| HAR | `log.entries[].request.url`（`postData` 一并收进 `raw`） |
| curl 命令行 | URL + `-X/-H/--data` |
| 普通清单 / stdin | 每行一条 |

然后喂进**同一条 oracle 链**，输出三态：

| 结论 | 判据 |
|---|---|
| `confirmed` | 至少一对实现产生了结构分歧（`level` 原样采信 `judge`，**不是报告方自述**） |
| `refuted` | 所有对的全部实现对这份输入理解一致 |
| `unverifiable` | 没有任何领域的解析器能接受它（`detail` 写清缺什么） |

单条失败绝不拖垮整批；CLI 是 `python -m ced verify`，控制台有对应标签页。

### 13.7 无 Docker 的真实链路（现场兜底）

- `ced/probe/front.py`：替身前置。模式 `pass` / `rewrite_cl` / `drop` / **参照实现策略名**。
  最后一档让"前置按自己的策略定帧、后端按另一套策略再定帧"真的发生在两个进程之间。
- `python -m ced serve --front --front-mode ref-te-first --policy ref-cl-first --front-port 18080`
  一条命令起链路；配 `ced/topologies/standin-front.yaml` 即可扫描。
- 真实 Docker 链路见 `docker/README.md`：**本机已装 Docker Desktop 4.93（F:\docker）并实机跑通**；
  8 项核验的结论、nginx 1.25.5 的实际定帧行为、以及本轮实测暴露并修掉的三个缺陷都记在那里。

### 13.8 探针领域化：真实链路不再只有分帧领域（缺陷修复）

**问题**：探针服务此前写死按分帧解析。`--domain url-norm` 把真实前置转发来的**完整请求**
（请求行 + 请求头 + 空行，80+ 字节）整个当成"裸对象"喂给 URL 归一化策略，
观测结果没有意义 —— 于是除分帧以外的四个领域**只有进程内验证，没有真实链路验证**。

**修法**：`DomainAdapter` 新增 `extract(raw) -> bytes` —— *从链路收到的字节里取出本领域要观测的那一段*。

| 领域 | 取哪一段 | 认不出完整请求时 |
|---|---|---|
| `http1-framing` | 原样（整条请求就是观测对象） | —— |
| `url-norm` / `enc-norm` | 请求行的 target | 原样 |
| `host-norm` | `Host` 头的值 | 原样 |
| `query-norm` | `?` 之后的查询串（无 `?` 则空） | 原样 |

"完整请求"由 `ced.adapters.base.http_request_fields` 判定（分帧结构完整 **且** 首行含 `HTTP/1.`），
因此**内置裸对象语料的行为一字不变**（47/47 反验证佐证）。
`probe.server` 与 `probe.evaluator.LocalEvaluator` 现在都走 `extract → parse`，两侧口径一致、可比较。

**实测**（`--domain url-norm`，前置 `--mode pass`；客户端发 `GET http://evil.com/a/../admin?x=1 HTTP/1.1` + `Host: Good.COM.`）：

| 控制口 | `raw_len` | 观测到的字段 |
|---|---|---|
| `:8811`（url-norm） | 83 | `norm_path=/admin`、`traversal=true` |
| `:8813`（host-norm） | 83 | `norm_host=Good.COM.` |

即：**整条请求进来，观测到的是本领域那一段**。覆盖测试见 `ced/tests/test_probe_domains.py`。

### 13.9 发现归并：报告不再被同一类事实淹没

**问题**：40 个用例就能产出上百条"安全级发现"，但它们其实是**同一对实现的同一类分歧**。
实测冗余倍数：`enc` 9.1×、`url` 5.9×、`query` 6.7×、`host` **15.0×** ——
报告里列上百条几乎相同的东西，真正有区分度的几类反而被淹没。

**修法**（`ced/report/cluster.py`）：判据做成**可机械执行**的，不靠人判断"像不像重复" ——

> **同一对实现 + 同一分歧类型 = 同一类事实**，只留一条代表。

代表选择确定：级别优先（有 `security` 就选它）→ 最小化后最短 → `case_id` 稳定排序。
`render_markdown` 的明细小节**每类只出一条**并标注"同类共 N 条"；JSON 的 `findings` **保留完整清单**，
另加 `clusters` 与 `redundancy` 两个字段（归并只是展示层的事，**绝不允许把发现弄丢** ——
`ced/tests/test_cluster.py` 用"条数守恒 + 分组键与条数完全对应"守住这条不变量）。


### 13.10 单一入口：自动识别 + 自动编排 + 实时链路（前端改成 3 个标签）

**问题**：此前用户要在几个入口之间自己选（原始字节 → 探测文件；别人的命中 → 验证外部发现；
主动搜 → 扫描控制台；真实产品 → 拓扑；本机流量 → 自动捕获）。**选择不该由用户做**。

**做法**：`ced/detect.py` 一个入口两条路由 ——

| 输入 | 路由 |
|---|---|
| 首行是 HTTP 请求行 | 扇出 5 个领域 → 逐对差分 → 消融判定 → 分级（安全级自带端到端 PoC） |
| nuclei / Burp / HAR / curl / 清单 | 解析成假设 → 同一条 oracle 链 → 已证实 / 未证实 / 证不了 |
| 认不出（含 pcap） | 当场报人话，并列出接受的形态与替代做法 |

编排过程**边跑边报**三种事件：`stage`（DAG 节点状态）、`report`（报告逐行）、`finding`（每定出一条）。
前端据此画 **DAG 实时进度** 与 **实时报告**；跑完的报告与实时吐出的行**逐字节一致**（有测试钉住）。

前端信息架构随之收敛为 **3 个标签**：`检测`（唯一入口，旧的四个入口收进同一页、全部常显，功能不减）、
`设置`（所有可配置项 + 模型 API 接入）、`自检`（反验证 + 内置案例库）。
**原有的 792 行前端 JS 一字未改**（新能力全在独立 IIFE 里，旧 id 一个未动）——
这条不变量由脚本核对：旧 JS 仍是新 JS 的逐字节子串。

**踩到的两个坑（都已修，且都有测试）**：

1. **textarea 存不住 CR**：浏览器的表单值规范化会把 `\r\n` 变成 `\n`，于是"粘贴一条原始请求"会
   静默丢掉 CRLF（实测：同样的 CL+TE，真 CRLF 判出 15 条安全级、LF 版判出 0 条）。
   修法：文件输入按**字节**读入（ArrayBuffer → 每字节映射一个字符），并**另存一份 exact 送检**
   （textarea 只作显示）；粘贴路径则在检测前**如实警告**换行已被规范化 —— 绝不替用户造字节。
2. **`ipam.aux_addresses` 不是"预留地址"**：见 13.8/docker README 的说明（写进去之后容器自己申请该地址也会撞）。

### 13.11 设置窗口：可配置项集中 + 密钥不入库
