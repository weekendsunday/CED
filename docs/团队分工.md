# 15 天 · 4 人任务分工（精简版）

**作品**：客户把产品交给我们 → 我们测出**产品之间的耦合误差**（两个产品串起来后，对同一份数据的理解不一致；单独跑都正常）。

**做法**：同一批请求灌进客户的产品链路 → 收集每个产品的"理解" → 比对 → 判定哪些有安全影响。

| 阶段 | 天数 | 目标 | 阶段末验收 |
|---|---|---|---|
| P1 最小闭环 | D1–D5 | 一条链路 + 2 个实现跑通 | ≥10 个误差，人工确认 ≥3 真实 |
| P2 判定与规模 | D6–D10 | 判定器 + 最小化 + 矩阵 + 反验证 | ≥6 实现接入；自动分级；1 例已知案例被重新挖出 |
| P3 交付 | D11–D15 | 端到端复现 + 报告 + 演示 | ≥3 个 `security` 误差，≥1 个端到端复现 |

**三条硬规则**

1. **C 的容器编排（D1–D3）阻塞所有人**，必须最先交付。
2. **B 的归一化定义与判定器不可延期**，它是"误差算不算漏洞"的唯一裁判。
3. **每阶段末冻结**；D10 是范围砍伐点，未达标就砍掉 P3 的第二领域，保交付。

---

## A｜领域与变异

> **一句话：负责「造请求」——想清楚该发什么，才逼得出误差。**

**核心交付物**：分歧轴模板 · 变异器 · 种子池

| 阶段 | 任务 |
|---|---|
| P1 | D1 把 6 类分歧轴（CL 解析 / TE 解析 / CL-TE 优先级 / chunk 语法 / 头解析 / 请求行）写成探测模板；D2 定向变异器 v0；D3 种子池 + 生成 ≥500 样本；D4–5 与 B 联调，按反馈调整变异方向 |
| P2 | D6 接入更多前置实现（haproxy / Envoy）；D7 接入后端实现（Tomcat / Go / h11）；D8 变异反馈优化（从盲变异改成**分歧导向**）；D9 补充样本 |
| P3 | D11 第二领域（URL / 路径归一化）最小可跑；D12 补充样本 + 复核；D13 冻结 |

**你自己要保证**：6 类分歧轴全覆盖；样本 ≥500；样本能真的逼出误差（不是无效请求）。

**依赖**：等 C 的链路（D1）。**被依赖**：B 的判定器全靠你的样本喂。

---

## B｜差分与判定 ★ 关键路径

> **一句话：负责「判」——定义什么叫"理解不一致"，以及"不一致算不算漏洞"。**

**核心交付物**：归一化定义 · **可升级性判定器**（平台的知识资产）

| 阶段 | 任务 |
|---|---|
| P1 | D1 视角数据结构 + 归一化初稿（谁跟谁比、比哪些字段）；D2 两实现的视角探针设计；D3 差分比对器 v0；D4–5 联调，产出首批误差并人工分级 |
| P2 | D6 **判定器 v1**（分歧→安全后果映射表落地）；D7 **消融定位承载者**（分歧由哪些攻击者可直接发送的字节承载）；D8 分级精度评估（对照人工标注）；D9 阈值标定（太松噪音爆炸、太严漏判） |
| P3 | D11 攻击场景模板（走私 / 绕过）；D12 打通端到端 PoC；D13 冻结 |

**你自己要保证**：判定器能自动分出 `security` / `compatibility` / `unknown`；`security` 精确率 ≥60%；至少 1 个已知案例被正确判定。

**依赖**：A 的样本、C 的链路。**被依赖**：C 的最小化和复现、D 的指标面板都吃你的分级结果。

**注意**：这是全队唯一不能延期的活。宁可先粗糙能跑，也不要晚交。

---

## C｜编排与复现

> **一句话：负责「让产品跑起来、串起来、可复跑」。**

**核心交付物**：容器编排 · 拓扑驱动 · 最小化 · 离线快照

| 阶段 | 任务 |
|---|---|
| P1 | **D1（最优先）** `docker-compose` 起最小链路：前置 → 探针后端，能发请求、能看到响应；D2 探针后端（记录收到的原始字节 → 输出解析视角）；D3 结果落库（SQLite）；D4 复跑幂等性 + 结果去重 |
| P2 | D6 拓扑 YAML 驱动起链路（改一行配置就能换链路）；D7 并行调度；D8 最小化（ddmin + 语义保持：压小后误差必须还在）；D9 **离线快照**（`docker save` 全部镜像） |
| P3 | D11 PoC 复现编排；D12 端到端复现；D13 冻结；D14 全量离线复跑 |

**你自己要保证**：一条命令起链路；同一实验复跑结果一致；**断网可跑**。

**依赖**：无（你是最上游）。**被依赖**：所有人。D1 交付得越早，全队越安全。

---

## D｜基准与交付

> **一句话：负责「证明有效 + 交付出去」。**

**核心交付物**：反验证用例 · 指标面板 · 报告 · 演示与文档

| 阶段 | 任务 |
|---|---|
| P1 | D1 仓库骨架、开发环境、**锁定镜像版本表**；D2 收集 3 个公开请求走私案例（做反验证素材）；D3 把已知案例改造成平台可跑的输入；D4 误差人工复核表（`security`/`compat`/`unknown` 标注口径） |
| P2 | D6 交叉矩阵设计（客户产品 × 参考实现）；D7 **内部基准反验证第一轮**（已知案例能否被重新挖出）；D8 指标面板（自动出数）；D9 指标数据落表 |
| P3 | D11 报告模板（误差清单 + 分级 + 修复建议）；D12 文档初稿；D13 报告自动生成接入；D14 录屏 + 视频备份；D15 打包交付 |

**你自己要保证**：≥1 个已知案例被平台**重新挖出**（这是"平台有效"的唯一证据）；指标能自动出数；报告 / 视频 / 快照齐全。

**依赖**：B 的分级结果、C 的快照。**被依赖**：最终交付物。
