## 0. 五分钟跑起来

**环境**：Python 3.11+。**零第三方依赖**，不需要 Docker，不需要联网。

```bash
cd F:/omp/CED-项目包

python main.py                     # ← 点这里：起网页界面，自动开浏览器（推荐）
```

浏览器会自动打开 `http://127.0.0.1:8777/`（端口被占会自动往后找，并打印实际地址）。
在这个窗口按 `Ctrl+C` 停止。

在 VSCode / PyCharm 里直接点运行按钮也可以 —— 运行的就是 `main.py`。

**`main.py` 的其它用法：**

```bash
python main.py --check             # 跑自检（测试 + 已知案例反验证）后退出
python main.py --no-open           # 只起服务，不打开浏览器
python main.py --port 9000         # 换端口
python main.py --probe             # 同时起探针服务（把真实产品接进来时用）
```

界面三个面板：

| 面板 | 做什么 |
|---|---|
| **探测文件** | 拖入一份请求文件 → 直接看有没有耦合误差、差在哪几个字节、算不算漏洞 |
| **内置案例** | 18 个已知分歧类别（两个领域各 9），点开看两侧观测与判定证据 |
| **自检** | 一键跑已知案例反验证，确认程序是好的 |

不想用界面就用命令行：

```bash
python -m ced impls                # 看有哪些参照实现与定向对照
python -m ced regression           # 已知案例反验证（改判定后必跑）
python -m ced probe 请求文件        # 探测一份原始字节文件
python -m ced scan --mode axis --limit 60 --out report.md --db ced.db
```

预期输出：

```
[结果] 用例 60 | 实现对 8 | 耦合误差 24 | 安全级 22
== 已知案例反验证：18/18 通过 ==
```

`ModuleNotFoundError: ced` → 说明你不在 `F:/omp/CED-项目包` 目录下。

## 1. 这个程序在干什么

客户把产品交给我们，我们找出它们在**串联处的耦合误差**。

$$\text{漏洞} \iff \text{语义分歧} \;\wedge\; \text{分歧点攻击者可控} \;\wedge\; \text{存在安全后果}$$

**最要紧的一句**：漏洞不在组件里，在**组件之间**。
单独看 nginx 没问题，单独看 gunicorn 没问题，`nginx + gunicorn` 就有 desync。

### 名词表

| 名词 | 一句话解释 |
|---|---|
| **耦合误差** | 两个产品对同一份字节的"理解"不一致 |
| **分歧轴** | 已知有分歧历史的语法点（CL 写法、TE 写法、chunk 语法…），共 6 条 |
| **参照实现** | 进程内可跑的、只在一个策略点上不同的实现，共 9 个（`ref-cl-first` 等） |
| **消融实验** | 逐条删掉请求头重放两侧；分歧消失 ⇒ 该头承载了它 ⇒ 攻击者可控 |
| **最小化** | ddmin 压缩样本，同时保持分歧仍在 |
| **链路（chain）** | 观测**真实前置转发出去的字节**，而不是它对外说的话 |

### 三种观测方式（runner）

| runner | 观测对象 | 用在哪 |
|---|---|---|
| `local` | 进程内参照实现 | 内部基准、可复现归因 |
| `socket` | 直连探针收到的字节 | 任意位置的字节流 |
| `chain` | 真实前置转发出去的字节 | **客户产品的真实链路** |

## 3. 日常操作手册（复制即用）

### 3.1 跑测试

```bash
python ced/tests/test_pipeline.py      # 引擎与判定（17 项）
python ced/tests/test_socket_probe.py  # 探针协议一致性（2 项）
python ced/tests/test_chain_e2e.py     # 前置→探针 端到端（5 项，自带替身前置）
```

**看到 `skipped` 要当失败处理。** 会跳过的测试等于不存在 —— 我们踩过：探针参数改名导致服务启动即退出，却显示 `OK (skipped=1)`。

### 3.2 已知案例反验证

```bash
python -m ced regression               # 全部案例跑一遍
python -m ced cases                    # 列出全部案例（id / 轴 / 对照 / 期望）
python -m ced case <id>                # 摊开一个案例：原始字节 + 两侧观测 + 判定
python -m ced case <id> --raw          # 只吐原始字节，可管道给 nc/curl 打靶
```

例：

```bash
python -m ced case request-line-absolute-uri
python -m ced case cl-te-conflict --raw | nc 127.0.0.1 8080
```

改过 `impls/http_reader.py`、`differ/`、`classify/`、`minimize/` **之后必须跑 `regression`**。

### 3.3 出报告

```bash
# 定向对照（8 对，归因清晰）
python -m ced scan --mode axis --limit 60 --out report.md --json report.json --db ced.db

# 交叉矩阵（36 对，用于发现未预设的分歧）
python -m ced scan --mode cross --limit 40 --out cross.md --db cross.db
```

产物：`report.md`（人看）、`report.json`（机器读）、`ced.db`（SQLite，每次扫描重建）。

### 3.4 起探针

```bash
python -m ced serve --policy ref-cl-first --data-port 8800 --api-port 8801
# probe ready: data=127.0.0.1:8800 api=127.0.0.1:8801 domain=http1-framing policy=ref-cl-first
```

**`--domain` 决定探针扮演哪个领域的后端**（默认 `http1-framing`）。分帧领域里"收到的字节"本身就是观测对象；
其余四个领域（`url-norm` / `host-norm` / `query-norm` / `enc-norm`）会先从收到的完整请求里
**取出本领域要观测的那一段**（请求行 target / Host 头值 / `?` 之后的查询串 / 路径），再按策略解析；
认不出是完整请求时原样当裸对象处理 —— 所以同一个探针端口既接直连的裸对象，也接真实前置转发的完整请求。
`--policy` 缺省取该领域的第一个参照实现。

实测（`--domain url-norm`，前置 `--mode pass` 转发 `GET http://evil.com/a/../admin?x=1 HTTP/1.1` + `Host: Good.COM.`）：
控制口 `/views` 里记下的是 `norm_path=/admin`、`traversal=true`，而不是把整条 83 字节请求当成裸对象。

### 3.5 接客户产品（拓扑）

```yaml
# my-topology.yaml
domain: http1-framing
impls:
  - id: customer-gateway       # 客户产品：runner=chain
    runner: chain
    endpoint: 127.0.0.1:8080   # 前置入口
    probe_api: 127.0.0.1:8801  # 前置**后面**那个探针的控制口
  - id: ref-cl-first           # 基准侧：本地参照实现
    runner: local
    policy: ref-cl-first
chain: [customer-gateway, ref-cl-first]
```

```bash
python -m ced scan --topology my-topology.yaml --mode cross --out customer.md
```

**链路不通时会中止且不产报告**，这是设计如此：

```
[!] 链路不可用，已中止（不产出任何结论）：前置 127.0.0.1:8080 后面的探针控制口 ... 不可达
```

宁可什么都不给，也不给一整片假阳性。

### 3.6 探测一份文件（任意原始字节）

手上有一份请求文件（抓包导出、别人给的 PoC、fuzz 样本），直接喂进去：

```bash
python -m ced probe req.bin                                  # 对 demo 拓扑的全部组合跑，只报有分歧的
python -m ced probe req.bin --pair ref-cl-first ref-te-first # 指定一对，并打印两侧完整观测
python -m ced probe req.bin --topology my.yaml               # 换成客户的拓扑
cat req.bin | python -m ced probe -                          # 从 stdin 读，可接管道
```

输出：原始字节 → 两侧观测 → 分歧字段 → 分类 → 判定 → 可控性证据 → 修复建议。

无分歧时会明确写「这不等于安全，只说明在这份输入上两侧没有分歧」，不会含糊过去。

> 探测**真实产品**时用 `--topology` 指向客户拓扑（见 §3.5）—— 那时被测对象是真实产品，不是参照实现。

### 3.7 让模型提一批提案（可选，不配也能跑）

```bash
python -m ced assist                     # 看配置状态；没配就直接告诉你"未配置"
python -m ced assist --propose 8         # 要 8 条提案，逐条跑差分 oracle 准入实验
python -m ced assist --ledger            # 命中率台账（模型 vs 手写轴，同一把尺子）
python -m ced scan --llm --limit 60      # 带模型提案跑一次扫描
python -m ced web                        # 控制台里勾「使用模型提案」
```

配置（任何 OpenAI 兼容端点）：

```bash
export CED_LLM_BASE_URL=https://api.deepseek.com/v1
export CED_LLM_MODEL=deepseek-chat
export CED_LLM_API_KEY=sk-...
```

Windows cmd 用 `set CED_LLM_BASE_URL=...`；控制台也可以只配前两个（本地端点通常不要密钥）。

**模型只提案，内核只裁决。** 一条提案要进语料必须连过两道门槛：

| 门槛 | 判据 | 不过怎么办 |
|---|---|---|
| ① 语法/白名单 | 能解析成 HTTP 消息，且落在分帧语法点上，且是**非规范**写法 | 丢弃，台账记「不可编译」 |
| ② 差分 oracle 准入实验 | 把候选字节真的喂给本地对照对，**真的逼出结构分歧** | 丢弃，台账记「未命中」 |

所以**幻觉进不了结果**：`Proposal` 类型里没有任何判定字段。
`--ledger` 里的「命中」= 逼出分歧的提案 / 全部提案，由内核给出，不看模型自述。

没配模型时全链路自动降级：提案返回空，扫描照跑，结果与不带 `--llm` 完全一致。

> 想把审过的提案固化下来、以后不再调模型也能用上？见 [3.15 固化语料](#315-固化语料把审过的提案写进仓库此后不再需要模型)。

> 合规：只把公开语料（RFC 分帧语法、已有轴名、命中率摘要）发给模型；
> **不发客户镜像、不发原始流量、不发客户拓扑文件。**

### 3.8 闭环 agent（模型看执行结果决定下一步）

```bash
python -m ced agent --rounds 4 --max-calls 12 --goal "在内置语料之外找出新的可升级耦合误差"
# 未配置模型时自动降级为单轮确定性扫描，结果与不带 agent 完全一致
```

模型只能调用 `scan_corpus / propose_axes / inspect / ledger / finish` 五个工具，
**没有任何工具能写出判定**；每条发现仍由 `classify.judge` 给出。
预算（轮数 × 工具调用数）是硬上限。输出：运行轨迹 + 合并结果 + 报告 + PoC。

> `propose_axes` 会额外向模型要一次提案（多花一次模型调用，但不占工具预算）。

### 3.9 端到端 PoC（只对 security 级）

```bash
python -m ced poc 8b2611d2                       # 摊开一条：场景 + 字节归属 + 步骤 + 脚本
python -m ced poc 8b2611d2 --stdout              # 只要脚本，管道给别处用
python -m ced scan --out report.md --poc-dir results/pocs   # 扫描时批量产出
```

生成的脚本零依赖，放在仓库任意位置都能跑：

```bash
python results/pocs/poc_8b2611d2.py              # 离线：算清字节归属（断言 PASS/FAIL）
python results/pocs/poc_8b2611d2.py --send 127.0.0.1:18080 --i-am-authorized   # 授权后真发
```

缺 `--i-am-authorized` 时**拒绝发送**并退出码 2 —— 这是刻意的合规闸门。

### 3.10 无 Docker 的真实链路（现场兜底）

比赛现场 Docker 起不来时的演示路径：

```bash
# 一条命令起链路：客户端 → 替身前置 → 探针（扮演后端）
python -m ced serve --front --front-mode ref-te-first --policy ref-cl-first \
       --data-port 8800 --api-port 8801 --front-port 18080

# 另开一个终端扫描
python -m ced scan --topology ced/topologies/standin-front.yaml --mode cross \
       --limit 30 --out results/standin.md --poc-dir results/pocs
```

`--front-mode` 可选 `pass` / `rewrite_cl` / `drop` / **参照实现策略名**。
最后一档最有价值：前置按自己的策略定帧、后端按另一套策略再定帧，真的发生在两个进程之间。

> 输出里会出现「**前置按自身策略拒绝了 N 条用例…已跳过**」—— 这是正常现象：
> 真实前置对畸形请求返回 4xx 且不转发，工具跳过并计数，**不合成观测、也不中止扫描**。

真实 Docker 链路（nginx 前置 + 探针后端、离线快照）见 `docker/README.md`；
**本机已装 Docker Desktop 4.93（`F:\docker`）并实机跑通** —— 核验结论与实测到的定帧行为见 `docker/README.md`。

### 3.11 两个领域：分帧 与 路径归一化

**加领域不改引擎**：换 `--domain` 就换一整套被测语义，差分 / 消融 / 判定 / 最小化 /
PoC / 报告 / 控制台全部原样复用。

```bash
python -m ced impls                              # 列出两个领域的参照实现与定向对照
python -m ced impls --domain url-norm            # 只看某一个领域

# 领域一：HTTP/1.1 分帧 → 请求走私（CWE-444）
python -m ced scan --domain http1-framing --mode axis --limit 60

# 领域二：URL/路径归一化 → 鉴权绕过（CWE-22 / CWE-863）
python -m ced scan --domain url-norm --mode axis --limit 60 --poc-dir results/pocs-url

python -m ced poc <case_id> --domain url-norm    # 摊开该领域的 PoC
```

| 领域 | 观测对象 | 参照实现 / 轴 | 能指出的漏洞类别 |
|---|---|---|---|
| `http1-framing` | 一条 HTTP/1.1 请求 | 9 / 8 | 请求走私 → 前置防护绕过（CWE-444） |
| `url-norm` | 一个请求目标 | 12 / 11 | 鉴权绕过 / 路径穿越，含过长 UTF-8、NUL 截断（CWE-22 / CWE-863） |
| `host-norm` | Host 头的值 | 9 / 8 | 虚拟主机绕过 / 缓存投毒（CWE-436） |
| `query-norm` | 查询串字节 | 11 / 10 | 参数污染（CWE-235） |
| `enc-norm` | 一段待解释的字节 | 10 / 10 | 过滤器绕过（CWE-180） |

> 五个领域的测试与反验证都在同一个自检里：`python main.py --check`。
> 已知案例按自己的 `domain` 字段选适配器（见 `ced/cases/known/*.json`），
> `python -m ced case <id>` 也按案例自己的领域选适配器。

### 3.12 验证外部发现（做扫描器的裁判）

把别人的命中当**待验证的假设**，用与扫描完全相同的链路给出三态结论 ——
**级别由内核给出，不看报告方的自述**：

```bash
python -m ced verify findings.json --format nuclei --out verify.md
python -m ced verify burp-sitemap.xml            # 按扩展名自动识别
cat urls.txt | python -m ced verify -             # 从 stdin 读
python -m ced verify list.txt --domain url-norm --domain host-norm   # 限定领域
```

| 结论 | 判据 |
|---|---|
| **已证实** | 至少一对实现产生了结构分歧（`level` 原样采信判定器） |
| **未证实** | 试过的这些领域里，所有实现对同一份输入理解一致（**不等于**这条发现是假的） |
| **证不了** | 没有任何领域的解析器能接受它（`detail` 写清缺什么） |

支持格式：nuclei（JSON/JSONL 的 `matched-at`）、Burp sitemap XML、HAR、curl 命令行、
普通清单（每行一条 URL）。检测页「**验证外部发现**」小节对应它。

### 3.13 自动捕获（本机代理，无需手动导出）

把浏览器 / 客户端 / 系统代理指向本机端口，请求**自动**进同一个差分 oracle ——
不用再拿 Burp 导出、也不用粘贴请求。

```bash
python -m ced capture --port 18081            # 默认端口 18081（避开 Windows 常保留的 8080）
python -m ced capture --jsonl capture.jsonl   # 顺便把每条记录追加成 JSONL（已 gitignore）
python -m ced capture --domain host-norm      # 只跑某个领域（可重复；缺省 = 全部 5 个）
python -m ced capture --analyze-all           # 连 .css/.js/图片也分析（默认跳过）
```

前台输出就是结果（本机实测，一条正常请求 + 一条重复 + 一条静态 + 一条 CL+TE 走私形态）：

```
[12:17:43] #1    GET 127.0.0.1/hello?x=1        分歧 0   一致      3.5ms
[12:17:43] #1    GET 127.0.0.1/hello?x=1   ×2   分歧 0   一致      3.5ms
[12:17:43] #3    GET 127.0.0.1/app.css           静态资源
[12:17:43] #4    POST 127.0.0.1/x               分歧 15  !! 安全级  2.0ms  http1-framing:15
                 └ http1-framing｜ref-cl-first ↔ ref-te-first｜framing_boundary CWE-444
```

一条请求**扇出 5 个领域**（靠适配器的 `extract` 各自取段：整条请求 / 请求行 target /
Host 头值 / 查询串 / 待解释字节），全跑一遍 2–3.5ms。

**三条必须知道的口径**：

1. **分析对象是"源站会看到的那份字节"**：客户端发给代理的请求行是绝对形式
   （`GET http://host/path HTTP/1.1`），代理先归一化成源站形式（`GET /path HTTP/1.1`）再分析。
   不归一化的话，项目里那条 `request-line-absolute-uri` 已知分歧轴会让**每条请求**刷出
   19 条安全级假阳性（实测数字）。原始字节不丢：记录里保留 `target` 与 `raw_b64`。
2. **HTTPS 不拆包**：`CONNECT` 只做隧道直通，列表里记一条"到 x:443（未拆）"。
   要看 HTTPS 明文得做 MITM（自签 CA + 手动信任），本期不做（见 README 能力边界）。
3. **同一份字节只分析一次**，重复出现只累加 `count`；静态资源默认跳过（仍然正常转发）。

**边界**：这是本机开发/测试用的代理，别设成生产出口；只用于你自有或已获授权的目标。

网页上也有同一件事（更省事）：**检测页 →「开始自动捕获」旁边的「捕获设置…」** ——
点开是个小窗（代理端口 / 领域 / 静态资源 / 记录文件 + 「存为默认」），关掉就开跑；
请求进来后列表实时出结果，点一行看证据、一键生成端到端 PoC。
`Esc` 或点窗外也能关。后端接口：
`/api/capture/{start,stop,state,records,record,poc}`。

### 3.14 单一入口（检测）与设置小窗

网页界面**只有一个页面**（没有标签栏）：`检测` 卡在最上面，`设置…` 是它右上角的按钮，
`自检` 与案例库直接排在同一页下方。**检测页就是唯一入口** ——
不用再想"我该用哪个工具"，把东西丢进去它自己判断：

| 你给什么 | 它自动走哪条路 |
|---|---|
| 一条 HTTP 请求的原始字节 | 扇出 5 个领域 → 逐对差分 → 消融判定 → 分级 |
| nuclei JSON / Burp XML / HAR / curl / URL 清单 | 解析成假设 → 同一条 oracle 链 → 已证实 / 未证实 / 证不了 |
| 都没有 | 点「开始自动捕获」让浏览器/客户端的请求自己流进来 |
| 乱码 / pcap | 当场报人话：列出接受的形态，并说明 pcap 请导出 HAR 或改用自动捕获 |

跑的时候：**DAG 实时显示跑到哪一步**（识别 → 取域 → 差分 → 判定 → 升级 PoC → 出报告），
**报告逐行实时吐**，跑完可一键复制 Markdown。发现清单里点一条看证据，安全级的自带端到端 PoC。

检测页的卡片顺序就是"看东西的顺序"（**不用滚**）：

| 顺序 | 卡片 | 什么时候看它 |
|---|---|---|
| 1 | **检测** | 粘/拖输入 + `开始检测` + `开始自动捕获`／`停止`／`捕获设置…` + 一行当前捕获参数摘要 |
| 2 | **自动链路** | 一进来就在首屏：状态条（运行中／已完成／失败 + 耗时）+ 六个节点实时变色 |
| 3 | **实时报告** | 边跑边吐的 Markdown，带 `复制报告` / `下载 .md` |
| 4 | **发现** | 分级徽章（安全级／疑点／兼容性）+ 清单 + 右侧证据／PoC |
| 5 | **自动捕获** | 请求流的水位：统计 + 清单 + 证据，点一行看证据／生成 PoC |

**捕获参数不占版面**：端口／领域／静态资源／记录文件都在「捕获设置…」小窗里
（原生 `dialog`：`Esc`、点窗外、右上角 `✕` 都是关），改完点「**存为默认**」写回设置页；
关窗不点保存则只影响这一次。当前值以一行摘要显示在按钮旁边，随时可见。

命令行等价物（同一套内核）：

```bash
python -c "from ced.detect import run; print(run(open('请求.bin','rb').read().decode('latin-1'))['summary'])"
```

**不用自己造输入**：仓库根的 `samples/` 有 15 个可直接用的样本（10 个原始请求覆盖 5 个领域 + 5 种外部格式），
网页上从「载入示例」下拉里挑一个就能跑；每个文件的实测结论见 `samples/README.md`，
并由 `ced/tests/test_samples.py` 盯着不许失真。

**设置小窗**（检测卡右上角「设置…」，原生 dialog：Esc / 点窗外 / ✕ 都能关）把可配置项收在一处，保存即生效：

| 分组 | 键 |
|---|---|
| 模型 API 接入 | `base_url` / `model` / `api_key` / `timeout` / `temperature` / `max_tokens`（写回 `CED_LLM_*`，服务启动时自动加载） |
| 自动捕获默认值 | `port` / `jsonl` / `analyze_all` / `domains` |
| 扫描默认值 | `domain` / `mode` / `limit` / `seed` |
| 输出路径 | `poc_dir` / `report_dir` |

配置落在仓库根的 `ced-settings.json`（**已 gitignore**，因为里面有密钥）；
`GET/POST /api/settings`，密钥只回显掩码（`******abcd`），拼错的键与错类型当场报人话。

**默认值真的生效**（这条是接口层的保证，不是文案）：

- 检测页的「捕获设置…」小窗在开页时按 `capture` 组的默认值**预填**；改了端口/领域/静态资源/记录文件，
  点小窗里的「存为默认」就写回设置页，改完的摘要立刻显示在按钮旁边。
- 起捕获时，**请求里没给的字段一律回落到设置里的默认值**（端口、领域、是否分析静态资源、记录文件），
  所以设置页不是摆设。
- 模型配置在服务启动时会被 `apply_llm_env()` 写进 `CED_LLM_*`，复用既有的读取路径。

### 3.15 固化语料（把审过的提案写进仓库，此后不再需要模型）

模型提案默认只活一轮：进当次语料，然后只剩台账里一行记录。想下次还用上它，就得
**重新调一次模型** —— 哪怕它上次已经逼出过真实的结构分歧。这条命令把审过的提案
固化成仓库文件：

```bash
python -m ced adopt                                       # 看台账里哪些够格（命中过的）
python -m ced adopt --add cl_obs_fold --add te_obs_fold   # 采纳进仓库文件
python -m ced adopt --drop cl_obs_fold                    # 撤下
```

落地在 `ced/cases/adopted/<领域>.json`，**进 git** —— 换机器、别人克隆都带着。此后
每次扫描（网页「内置矩阵扫描」也好、`python -m ced scan` 也好、`ced agent` 也好）
都会自动带上它，**不再需要模型**；不勾「使用模型提案」也带。

只认台账里 `admitted=1` 的 `llm` 条目 —— 采纳的前提是它真的逼出过分歧，不是模型
自己说得好。三条口径：

1. **不是新来源**：payload → 同一个 `proposal_id`，台账仍记 `origin=llm`，报告里照样
   显示"这是哪个模型猜的、当初的理由是什么"（发现详情页的「模型线索」栏）。
2. **不绕门槛**：加载后照样重跑差分 oracle 准入实验，没逼出分歧的就地丢弃 ——
   固化省的是模型调用，不是门槛。手改文件塞一条不会分歧的进去，门槛照样拦得住。
3. **只进人手**：只有 `--add` 写得进来，代码绝不自动采纳；提交前自己 review，
   写进去就等于把它当内置语料了。

台账没有领域列，所以 `--add` 只按轴名找；跨领域的旧条目会在准入实验里被当前领域的
对照自然筛掉，不必在这条命令里拦。

## 4. 扩展任务怎么做

### 4.1 加一个参照实现（A）

```python
# ced/impls/reference.py
REFERENCES["ref-my-policy"] = _p("ref-my-policy", cl_syntax="lenient")

# 想让它参与定向对照，再加一行：
AXIS_PAIRS["my_axis"] = ("ref-cl-first", "ref-my-policy")
```

约定：**每个参照实现只偏离基线一个策略点** —— 这样每个分歧都能归因到具体策略。

验证：`python -m ced impls` 应列出它；`python -m ced regression` 不应变红。

### 4.2 加一条分歧轴（A）

```python
# ced/mutate/axes.py
# ① 登记轴名
AXES = ("cl_value", "te_value", "cl_te_conflict",
        "chunk_syntax", "header_syntax", "request_line", "my_axis")

# ② 写语料
def case_my_axis() -> list[bytes]:
    return [
        build(headers=[HOST, (b"X-Thing", b"a")]),
        build(headers=[HOST, (b"X-Thing", b"b")]),
    ]

# ③ 注册构造器
_BUILDERS["my_axis"] = case_my_axis
```

验证：`python -c "from ced.mutate import corpus; print(len(corpus()))"` 应变大。

### 4.3 加一个已知案例（D）

先算出 payload 的 base64：

```bash
python -c "import base64;print(base64.b64encode(b'POST / HTTP/1.1\r\nHost: localhost\r\n\r\n').decode())"
```

再写 `ced/cases/known/my-case.json`：

```json
{
  "id": "my-case",
  "axis": "my_axis",
  "left": "ref-cl-first",
  "right": "ref-te-first",
  "expect_kind": "framing_boundary",
  "expect_fields": ["consumed"],
  "payload_b64": "<上一步的输出>",
  "reference": "RFC 9112 6.x / 公开研究出处",
  "note": "这个案例为什么算已知分歧"
}
```

> **红线**：`expect_kind` 与 `expect_fields` 必须来自 RFC 或公开资料，
> **不能用工具当前的输出反向填** —— 那样回归就只是自己验证自己。

验证：`python -m ced regression` 应显示 `[PASS] my-case`。

### 4.4 加一个领域适配器（A，第二阶段）

```python
# ced/adapters/my_domain.py
class MyDomainAdapter:
    name = "my-domain"
    compare_keys = ("field_a", "field_b")     # 只放结构字段！
    boundary_kinds = ("boundary",)
    kind_acceptance = "acceptance"

    def meta(self, kind):                      # 类型 → 后果/CWE/场景/修复
        return {"effect": "...", "cwe": "CWE-XXX", "scenario": "bypass", "fix": "..."}
    def specs(self): ...                       # 参与差分的实现
    def corpus(self): ...                      # 种子语料
    def expand(self, cases, rng): ...          # 定向变异
    def classify(self, diff_keys): ...         # 分歧字段 → 类型
```

```python
# ced/adapters/__init__.py
ADAPTERS[MyDomainAdapter.name] = MyDomainAdapter
```

引擎（差分 / 判定 / 最小化 / 报告 / 落库）**一行都不用改**。

验证：`python -m ced scan --domain my-domain --out r.md`

### 4.5 接一个真实产品（C）

1. 在客户产品**后面**起探针：`python -m ced serve --policy ref-cl-first --data-port 8800 --api-port 8801`
2. 写拓扑（见 §3.5），客户产品用 `runner: chain`
3. `python -m ced scan --topology my-topology.yaml --mode cross --out customer.md`

需要 Docker 时，把客户产品的 compose 写进 `ced/topologies/`，
只要探针的控制口在 `probe_api` 上可达即可 —— `chain` 不关心前置是怎么起的。

## 5. 红线（这几条踩了等于白做）

1. **不许为了变绿改期望值。** 回归红了先判断是工具错还是期望错；改 `expect_kind`/`expect_fields` 必须在 commit 说明里写清依据。
2. **探测失败一律抛错，绝不许合成观测。** 合成出来的观测必然与基线不同，会把"没跑通"变成成片的假阳性安全结论。
3. **不许把诊断字段加进 `compare_keys`。** 那会让"报错文案不同"被升级成漏洞（diffmine 就是这么错的）。有测试守着这条。
4. **`skipped` 当失败处理。** 沉默跳过的测试比崩溃更危险。
5. **提交前清理**：`__pycache__/`、`*.db`、报告产物都不进包（见 `ced/.gitignore`）。
6. **压缩提交件时别用 Windows 资源管理器右键压缩** —— 它把中文文件名按 GBK 存进 ZIP，换台机器解压会变成 `╬─╝■` 乱码（这个坑踩过）。用 7-Zip，或 `python -m zipfile -c out.zip 目录名`。
7. **只对本地容器矩阵或已授权链路运行。** 赛题第九条明确禁止以竞赛为由实施未授权测试 —— 这条也写在作品报告的合规性章节里。
8. **不许让模型产出判定。** 大模型只能通过 `Proposal` 影响"往哪里搜"；`Verdict` 的唯一生产者是 `classify/upgradability.py::judge()`。给 `Proposal` 加判定字段、或把模型自述直接写进报告当结论 = 自毁核心创新点。

## 6. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: ced` | 不在 `F:/omp` 下执行 | `cd F:/omp` |
| `链路不可用，已中止` | 前置没起，或探针控制口不通 | 确认 `endpoint` / `probe_api`；起探针或 compose |
| 测试 `skipped` | 探针/前置没起来 | **当失败查**，别放过 |
| 扫描出 0 分歧 | 前置是透明的（没改写字节） | 正常；换会改写的前置或换语料 |
| 回归变红 | 改过解析/判定/最小化 | 先看是工具错还是期望错（红线 1） |
| 报告里出现非常规观测值 | 探针策略与基准策略不一致 | 两侧应使用同一解析真源 |
| `未知领域` | `--domain` 名字没登记 | 见 §4.4 |
| `assist --propose` 报「模型不可用」 | 端点 / 密钥 / 网络不通 | 核对 `CED_LLM_BASE_URL`；未配置属正常降级，不影响扫描 |
| 提案全是「未命中」 | 模型提的都是规范请求 | 正常现象，说明没打在分帧语法点上；看台账 `note` 里的具体原因 |
| 控制台「结果已不在内存」 | 服务重启过，结果对象不再可读 | 任务记录仍在 `ced.db`；重新跑一次即可 |
| 控制台「请求失败：**连不上本机服务**…」 | 请求根本没到服务端 | 看启动它的那个窗口还在不在；**若浏览器 / 系统代理曾被指向自动捕获端口（默认 18081），停止捕获后要改回去**，否则整页请求都会失败 |
| 控制台「请求失败：**HTTP 500：服务端异常**…」 | 某个接口处理函数抛异常 | 现在服务端异常**一律回 JSON**（不再回一页 HTML），错误信息带 `where`（哪个接口）+ 异常类型；完整 traceback 打在启动窗口里，照着修 |
| 控制台「请求失败：**返回不是 JSON**…」 | 响应体被别人改写成了非 JSON | 一般是被中间层/代理替换了响应；核对浏览器代理设置，环境干净时不会出现 |
